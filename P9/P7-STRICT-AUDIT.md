# ตรวจ P7 เทียบ Java แบบนับทุกแอตทริบิวต์และเมธอด

แหล่งเทียบหลัก: [Canva P7 ฉบับที่ผู้ใช้ยืนยัน](https://www.canva.com/design/DAHXaK2zQ38/3Sd-YVMVB1DkWuToNWdsRQ/edit) หน้า 270–289 ของสำเนา **382 หน้า** ตรวจข้อความกล่อง UML จาก Canva อีกครั้งวันที่ 2 พฤศจิกายน 2026 และเก็บข้อความที่อ่านไว้ใน `P7-CANVA-LATEST.json` ไม่นับโน้ต P6 เป็นเมธอด เพราะบางโน้ตอ้างกริยาคนละเรื่อง

**ผลตรวจชื่อคำล่าสุด:** ชื่อ field ใน P7 ทั้ง **101 ชื่อ** มีอยู่ใน Java ครบ และชื่อ operation ทั้ง **73 ชื่อ** มีครบ ปรับชื่อพารามิเตอร์ของ operation ให้ตรงสไลด์แล้ว ตรวจซ้ำได้ด้วย `python3 P9/check_p7_contract.py` เหลือจุดต่าง 5 รายการ ซึ่งเป็นชนิด `Map` ใน P7 เทียบกับ `List` ในโค้ด ได้แก่ `Menu.options`, `Recipe.ingredients`, `PurchaseOrder.orderedQty`, `PurchaseOrder.receivedQty` และพารามิเตอร์ของ `PurchaseOrder.receive()`

**แก้ความเข้าใจเรื่อง Customer:** หน้า 271 ของ Canva และ `src/model/Customer.java` มี `checkCustomerStatus() : boolean` ทั้งคู่แล้ว เมธอดคืน `true` เมื่อผูก `Member` ไว้; ลบ `getCustomerId()` และ `isMember()` ที่ไม่มีผู้เรียก แล้วเปลี่ยน `getMember()`/`setMember()` เป็น `linkedMember()`/`linkMember()` เพื่อใช้ผูกสมาชิกภายหลัง

ตรวจทั้ง 16 ไฟล์รอบล่าสุด: ลบเมธอด `get...` ที่ไม่มีผู้เรียกอีก 12 ตัว และเปลี่ยนชื่อเมธอดอ่าน/แก้ข้อมูลที่ยังต้องใช้เป็นชื่อสั้นตามข้อมูลหรือการกระทำ เช่น `price()`, `stockQty()`, `rename()` และ `changePhone()` ใน `Main`, `model` และ tests ทั้งหมด ข้อยกเว้นคือ `SOP.getTotalMinutes()` และ `Member.setRule()` เพราะ **สองชื่อนี้เขียนอยู่ใน P7 จริง**

ตรวจชนิดพารามิเตอร์และชนิดค่าคืนด้วย: **72 จาก 73 operation ตรง P7 ทั้งชื่อพารามิเตอร์และชนิด** จุดที่ต่างเพียงรายการเดียวคือ `PurchaseOrder.receive(qtys : Map<Ingredient, Double>) : void` ใน P7 แต่ Java ใช้ `receive(List<Double> qtys)` ตามข้อกำหนดก่อนหน้าที่ให้ใช้ List เท่านั้น

ตัวนับ Java ด้านล่างนับ private field, public constructor และ public method ทั้งหมด รวมเมธอดอ่านข้อมูลที่ `Main` ใช้งานและ overload ไม่นับ enum เป็นคลาสโดเมนเพิ่ม

## ประเด็นที่ต้องตัดสินใจก่อนแก้โค้ด

1. คำขอล่าสุดให้จำนวนและชนิด field ตรง P7 ทุกตัว แต่ก่อนหน้านี้ผู้ใช้ขอให้ใช้ `List` เท่านั้น ซึ่งขัดกับ `Map` ใน P7 ของ `Menu`, `Recipe` และ `PurchaseOrder`
2. P7 ไม่แสดงเมธอดอ่านข้อมูลส่วนใหญ่ แต่ `Main` ต้องอ่าน private field ไปแสดงผล แม้เปลี่ยนชื่อจาก `getName()` เป็น `name()` แล้ว จำนวน operation ก็ยังมากกว่า P7 ถ้าจะให้จำนวนเท่ากล่องเป๊ะต้องออกแบบ `Main` และโมเดลใหม่ทั้งระบบ
3. P7 ไม่มี field สำรองข้อมูลราคา/สูตรใน `OrderItem`, ไม่มี `order` ใน `Payment` และไม่มีสถานะโต๊ะ การคงผลรัน Text Mode เดิมพร้อมลด field ให้เท่า P7 จึงต้องออกแบบทางเก็บข้อมูลใหม่ ไม่ใช่ลบเมธอดอย่างเดียว
4. ตรวจ Canva ได้เมื่อส่ง **ลิงก์เต็มพร้อม collaboration token**; การส่งเพียง design ID ทำให้เข้าถึงผิดพลาดในครั้งแรก ข้อความ P7 ในลิงก์นี้ตรงกับ HTML P7 ที่ใช้ทำตาราง
5. ข้อความโน้ต P7 มีจุดที่อ้างอิง P6 คนละเรื่อง เช่น `Supplier.supplies()` ถูกโยงกับการตรวจเบอร์โทรสมาชิก และโน้ต `Member.earnPoints()` ระบุ 25 บาทต่อแต้ม ขณะที่ข้อมูลตัวอย่าง/โค้ดปัจจุบันใช้ 50 บาทต่อแต้ม จึงต้องแยกการตรวจกล่อง UML ออกจากการตรวจความถูกต้องของโน้ต

**ข้อสรุป:** ชื่อ operation ทั้ง 73 รายการของ P7 มีใน Java แล้วเมื่อเทียบตามชื่อ แต่จำนวน field และ public method ยังไม่เท่ากล่อง UML โดยเฉพาะ `Map` ใน P7 กับ `List` ที่ผู้ใช้ขอให้ใช้ในโค้ด เมธอดทั่วไปชื่อ `get...`/`set...` ถูกลบหรือเปลี่ยนชื่อแล้ว ยกเว้นสองชื่อที่ P7 ระบุเอง; constructor ใช้ตั้งค่าเริ่มต้น แต่ไม่ช่วยอ่านหรือแก้ข้อมูลภายหลัง
