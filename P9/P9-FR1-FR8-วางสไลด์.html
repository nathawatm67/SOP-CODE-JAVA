สไลด์ 11 — ทฤษฎี OOP และ Composition

ตามโครงทฤษฎีใน PDF ตัวอย่าง หน้า 2 (สไลด์ 339): Class เป็นแบบพิมพ์, Object คือสิ่งที่สร้างจาก class, field เก็บข้อมูล, constructor ตั้งค่าแรก และ method ทำงานเมื่อถูกเรียก ดู Oracle Java: Classes and Objects

Composition คือความสัมพันธ์ has-a แบบเจ้าของกับส่วนย่อย: Order ◆ OrderItem และเพชรทึบอยู่ฝั่ง Order ส่วนย่อยหนึ่งอยู่ใน composite ได้ไม่เกินหนึ่งตัว ณ เวลาหนึ่ง ตาม OMG UML 2.5.1 §11.2.3 วิธีหา: อ่าน Use Case → หา “A มี B” → ถามว่า B ยังมีความหมายไหมเมื่อไม่มี A → ดู field และการสร้าง/ทำลายในโค้ด

ตัวหลักส่วนย่อยจุดที่เห็นในโค้ด
OrderOrderItemOrder.destroy() วนเรียก item.destroy()
MenuRecipeMenu.destroy() วนเรียก recipe.destroy()
SOPSOPStepSOP.destroy() วนเรียก step.destroy()
IngredientStockMovementIngredient.destroy() วนเรียก movement.destroy()
MemberPointTransactionMember.destroy() วนเรียก transaction.destroy()

โค้ดนี้จำลองการสิ้นสุดส่วนย่อยด้วย destroy(); Java จัดการหน่วยความจำภายหลัง อ่านคำอธิบายทีละขั้นและตัวอย่าง Association ที่ต่างกันได้ใน P9-THEORY.md

สไลด์ 12 — โค้ด Composition: Order และ Menu

โค้ดจริงจาก src/model/Order.java และ src/model/Menu.java:

// Order เป็นเจ้าของ OrderItem
public void destroy() {
    for (int i = 0; i < items.size(); i++)
        items.get(i).destroy();
    items.clear();
    table = null;
    customer = null;
    payment = null;
    destroyed = true;
}

// Menu เป็นเจ้าของ Recipe
public void destroy() {
    for (int i = 0; i < recipes.size(); i++)
        recipes.get(i).destroy();
    recipes.clear();
    optionNames.clear();
    optionPrices.clear();
    extraOptionIndexes.clear();
    extraIngredients.clear();
    extraQuantities.clear();
    destroyed = true;
}

table = null เป็นเพียงการเลิกอ้างถึงโต๊ะ ไม่ใช่ Composition; โต๊ะยังอยู่ในรายการของร้าน
