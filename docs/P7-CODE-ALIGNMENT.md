# เทียบโค้ดกับ Class Diagram P7 (16 คลาส)

โปรแกรมเริ่มที่ `src/Main.java` ส่วน `src/model` มี 16 ไฟล์ตามกล่องคลาส P7 ตารางนี้บอกเมธอดหลักที่ดูได้ในโค้ด เมธอดอ่านข้อมูลที่จำเป็นมีชื่อสั้น เช่น `name()` และ `price()`

| คลาส P7 | สิ่งที่ตรงกับแผนภาพและใช้เล่าได้ |
|---|---|
| Employee | เก็บรหัส ชื่อ บทบาท `Role`; ตรวจบทบาทด้วย `authenticateRole()` และมอบหมายสถานีด้วย `assignStationDuty()` |
| Customer | เก็บรหัสและสมาชิกที่อาจว่าง; `checkCustomerStatus()` บอกว่าผูกสมาชิกหรือยัง |
| Member | เก็บข้อมูลและประวัติแต้ม; `earnPoints()`, `redeemPoints()`, `setRule()`, `validateRedeem()` |
| Table | เก็บรหัสกับ QR; `scanTableQRCode()` แล้ว `identifyTableNumber()` |
| Order | เก็บโต๊ะ ลูกค้า รายการ สถานะ `OrderStatus` และยอดรวม; เพิ่ม/ลบรายการ แนบสมาชิก ยืนยัน คำนวณยอด ยกเลิก และเปลี่ยนสถานะตามขั้นตอน |
| OrderItem | เก็บจำนวน ราคา สูตร เครื่องปรุง หมายเหตุ สถานะ `ItemStatus` และคำขอ; เริ่มปรุง ทำเสร็จ เสิร์ฟ ยกเลิก เทียบเวลา ขอแก้ และให้ผู้จัดการตัดสินใจ |
| Menu | เก็บราคา หมวด สถานี สูตรหลายเวอร์ชัน ตัวเลือกชื่อ/ราคาใน `List` สองชุด และ `SaleStatus`; เปิด/ปิดขาย |
| Recipe | เก็บเวอร์ชัน `RecipeStatus` และส่วนผสม/ปริมาณใน `List` สองชุด; เพิ่มวัตถุดิบ เปลี่ยนปริมาณ ทำสูตรสมบูรณ์ และสร้างเวอร์ชันใหม่ |
| SOP | เก็บเมนู ขั้นตอน และ `SopStatus`; แก้ชื่อ เผยแพร่ ปิด/เปิดใช้ และรวมเวลามาตรฐาน |
| SOPStep | เก็บรหัส ลำดับ `no` คำอธิบาย และเวลามาตรฐาน |
| Ingredient | เก็บยอดคงเหลือและประวัติ; ตรวจพอ ตัด คืน รับเข้า ปรับยอด และแก้ข้อมูล |
| StockMovement | เก็บเวลา `MovementType` ปริมาณ ยอดหลังเปลี่ยน เอกสารอ้างอิง เหตุผล และผู้ทำรายการ |
| PurchaseOrder | เก็บสถานะ `PoStatus` ผู้จำหน่าย ผู้สร้าง และวัตถุดิบ/จำนวนสั่ง/จำนวนรับใน `List` สามชุด; เพิ่มรายการ สั่ง และรับของ |
| Supplier | เก็บรหัส ชื่อ และ `suppliedIngredients`; `addIngredient()` กับ `supplies()` ตรงภาพตัวอย่าง |
| Payment | เก็บ `PayMethod` เงินรับ เงินทอน ส่วนลด เลขใบเสร็จ เวลา และผู้รับเงิน; คำนวณส่วนลด/เงินทอน จ่าย ยืนยัน และสร้างข้อความใบเสร็จ |
| PointTransaction | เก็บวันเวลา `PointType` จำนวนแต้ม ยอดคงเหลือ และใบชำระที่เกี่ยวข้อง |

## เหตุผลที่ยังมีเมธอดนอกแผนภาพ

- P7 ระบุ `Map` สำหรับข้อมูลคู่บางจุด แต่โค้ดฉบับเรียนรู้ใช้ `List` หลายชุดตามคำขอของผู้ใช้ ข้อมูลที่ตำแหน่ง `i` ในแต่ละ List เป็นเรื่องเดียวกัน และเมธอดของคลาสเป็นผู้เพิ่ม/แก้ค่าเพื่อรักษาตำแหน่งให้ตรงกัน จึง **ไม่ตรงชนิด field ใน P7 ตรงตัว**

- P7 เป็นภาพโครงสร้างหลัก ส่วน `Main` ยังต้องมีเมธอดอ่านข้อมูลไปแสดง เช่น `name()` และ `statusText()` การมี Constructor ไม่ได้ทำให้ Main อ่าน private field ได้
- เมธอดเปลี่ยนข้อมูลภายหลัง เช่น `Member.changePhone()` และ `OrderItem.changeNote()` รองรับ UC08 และ UC01 ส่วนสถานะสำคัญเปลี่ยนผ่านเมธอดที่มีกฎ เช่น `confirm()`, `markReady()` และ `pay()`
- Constructor และเมธอดบางตัวมีรูปแบบรับค่าเพิ่มเพื่อรองรับข้อมูลจริงของทั้ง 8 Use Case เช่น `Order(id, table, customer)`, `Payment.pay(method, received, points)` และ `PurchaseOrder.receive(ArrayList)`; รูปแบบใน P7 ก็มีให้เรียกได้
- `Table` มีจำนวนที่นั่ง/สถานะ, `OrderItem` มีสำเนาราคาและสูตร, `Payment` มียอดสุทธิและแต้ม เพราะหน้าจอและกฎของระบบต้องใช้ข้อมูลเหล่านี้
- `OrderItem.changeStatus()` จำกัดการเปลี่ยนที่ข้ามขั้นตอน เพื่อไม่ให้หลบกฎตัดสต็อกหรือเสิร์ฟก่อนปรุง ใช้ `startCooking()`, `markReady()` และ `serve()` สำหรับขั้นตอนจริง

## ตัวอย่างอธิบาย Constructor กับเมธอดอ่านข้อมูล

```java
Supplier supplier = new Supplier("S1", "ร้านส่งปลา"); // Constructor ใส่ค่าเริ่มต้น
supplier.addIngredient(fish);                          // เพิ่มข้อมูลภายหลัง
System.out.println(supplier.name());                  // อ่าน private field ไปแสดง
System.out.println(supplier.supplies(fish));           // ให้ object ตรวจเงื่อนไขเอง
```

ทดสอบด้วย `python3 tests/run_tests.py` ซึ่งตรวจ model และเส้นทางเมนูทั้ง 8 งาน
