# คู่มืออธิบายโปรแกรมร้านข้าวต้มอารมณ์ดี แบบอ่านตามขั้นตอน

เอกสารนี้เขียนสำหรับคนเริ่มเรียน Java และคนที่ต้องนำเสนอโค้ด อ่านตามลำดับได้เลย หากมีเวลาน้อย ให้อ่านหัวข้อ 1, 3, 5 และ 8 ก่อน

## 1. โปรแกรมนี้ทำอะไร

โปรแกรมจำลองระบบร้านอาหารในหน้าจอข้อความ (Terminal) มีงาน 8 ด้าน: สั่งอาหาร, จัดการ SOP, ปรุงและเสิร์ฟ, ชำระเงิน, สต็อก, รายงาน, เมนูและสูตร, สมาชิกและแต้ม ทุกอย่างใช้ข้อมูลร้านชุดเดียวกันตลอดเวลาที่โปรแกรมเปิดอยู่

ไฟล์ที่ใช้เริ่มรันคือ `src/Main.java` ส่วน `src/model` มี 16 คลาสตามกล่อง Class Diagram P7 โดยแต่ละคลาสแทนสิ่งหนึ่งอย่างในร้าน เช่น `Order` แทนออเดอร์ และ `Ingredient` แทนวัตถุดิบ

```text
ผู้ใช้พิมพ์คำตอบ
       ↓
Main อ่านคำตอบและแสดงหน้าจอ
       ↓
Main เรียกเมธอดของ object ใน model
       ↓
object ตรวจเงื่อนไขและเปลี่ยนข้อมูลของตัวเอง
       ↓
Main เรียกเมธอดอ่านข้อมูล เช่น `name()` แล้วแสดงให้ผู้ใช้เห็น
```

ตัวอย่าง: เมื่อผู้ใช้กดยืนยันออเดอร์ `Main` เรียก `order.confirm()` ส่วน `Order` ตรวจสต็อกและเรียก `ingredient.deduct(...)` เอง หน้าจอไม่ต้องคำนวณยอดสต็อกซ้ำ

## 2. คำ Java ที่จำเป็นก่อนอ่าน

| คำ | ความหมายง่าย ๆ | ตัวอย่างในงาน |
|---|---|---|
| class | แบบสำหรับสร้างสิ่งชนิดหนึ่ง | `Ingredient` เป็นแบบของวัตถุดิบ |
| object | สิ่งที่สร้างจาก class | `fish` เป็นวัตถุดิบเนื้อปลาหนึ่งตัว |
| field | ข้อมูลที่ object เก็บ | `stockQty` คือยอดปลาในคลัง |
| Constructor | เมธอดที่ทำงานตอน `new` | `new Ingredient(...)` ใส่ชื่อและหน่วยเริ่มต้น |
| method | งานที่ object ทำได้ | `deduct()` หักสต็อก |
| `private` | ซ่อนข้อมูลไม่ให้ภายนอกเปลี่ยนตรง ๆ | `stockQty` เปลี่ยนผ่านเมธอดของ `Ingredient` |
| เมธอดอ่านข้อมูล | อ่านข้อมูลที่ยังเก็บเป็น private | `stockQty()` อ่านยอดคงเหลือ |
| เมธอดเปลี่ยนข้อมูล | เปลี่ยนข้อมูลหลังสร้าง object | `changePhone()` เปลี่ยนเบอร์สมาชิก |
| `ArrayList` | รายการที่เพิ่ม/ลบได้ | `orders` เก็บออเดอร์หลายใบ |
| `List` | ชนิดรายการหลายค่า | สูตรมีรายการวัตถุดิบและรายการปริมาณ |
| `ArrayList` | class ที่สร้าง object ให้ตัวแปรชนิด `List` | `new ArrayList<Ingredient>()` |
| `enum` | ชุดค่าที่เลือกได้จำกัด | `OrderStatus.CART`, `PAID` |
| `static` | ข้อมูล/เมธอดร่วมของคลาส | กฎแต้มใน `Member` ใช้ร่วมกันทั้งร้าน |
| `null` | ยังไม่มี object ที่อ้างถึง | ลูกค้าที่ไม่เป็นสมาชิกมี `member == null` |
| `return` | คืนค่าให้จุดที่เรียก | `calculateTotal()` คืนยอดเงิน |
| `throw` | แจ้งว่าเงื่อนไขไม่ผ่าน | สต็อกไม่พอจึงยืนยันไม่ได้ |

## 3. อ่าน `Main.java` จากบนลงล่างอย่างไร

### 3.1 ข้อมูลกลางของร้าน

ด้านบนของ `Main` มี `tables`, `menus`, `ingredients`, `members`, `sops`, `orders` และ `purchaseOrders` เป็น `ArrayList` คนละชุด แต่ละรายการเก็บ object จริง ไม่ใช่แค่ข้อความชื่อ พนักงานตัวอย่าง 3 คนถูกสร้างเป็น `manager`, `cashier`, `cook`

เมธอดเหล่านี้อยู่ในคลาส `Main` เดียวกัน จึงอ่านรายการชุดเดียวกันได้ เช่น เมื่อ UC01 เพิ่ม `Order` ลง `orders` แล้ว UC03 จะเห็นออเดอร์นั้นในคิวครัว

### 3.2 จุดเริ่ม `main()`

1. เรียก `createSampleData()` เพื่อสร้างโต๊ะ เมนู สูตร วัตถุดิบ SOP ผู้จำหน่าย และสมาชิกตัวอย่าง
2. เข้า `while (running)` เพื่อแสดงเมนูหลักซ้ำ
3. เรียก `readInt()` อ่านตัวเลือก 0 ถึง 8
4. เรียก `uc01()` ถึง `uc08()` ตามตัวเลขที่เลือก
5. เมื่อเลือก 0 จะตั้ง `running = false` และออกจากลูป

`try/catch` รอบเมนูรับข้อผิดพลาดที่ model แจ้ง เช่น สต็อกไม่พอ แล้วพิมพ์เหตุผลแทนการปิดโปรแกรมทันที

### 3.3 เมธอดช่วยรับคำตอบ

- `readText()` อ่านหนึ่งบรรทัดแล้วตัดช่องว่างหัวท้าย
- `readRequired()` ถามซ้ำจนได้ข้อความ
- `readInt()` และ `readNumber()` ถามซ้ำจนได้ตัวเลขในช่วงที่กำหนด
- `confirm()` เปลี่ยนคำตอบ 1/0 เป็น `true`/`false`
- `chooseMenu()`, `chooseIngredient()`, `chooseOrder()` แสดงรายการและคืน object ที่เลือก ตัวเลขบนหน้าจอเริ่มที่ 1 แต่ตำแหน่ง `ArrayList` เริ่มที่ 0 จึงใช้ `choice - 1`

### 3.4 ทำไม Main ยาว

ผู้ใช้ต้องการให้หน้าจอทั้ง 8 งานอยู่ในไฟล์ `Main.java` จึงมีเมธอด `uc01()` ถึง `uc08()` อยู่รวมกัน แต่กฎสำคัญ เช่น การตัดสต็อก การจ่ายเงิน และการเปลี่ยนสถานะ อยู่ใน object ของ `model`

## 4. คลาส 16 ตัวใน P7 ทำหน้าที่อะไร

### คนและโต๊ะ

1. **Employee** เก็บรหัส ชื่อ และ `Role` ของพนักงาน เมธอด `authenticateRole()` ใช้ตรวจบทบาท ส่วน `assignStationDuty()` กำหนดสถานีครัว
2. **Customer** แทนลูกค้าที่เปิดออเดอร์ อาจมีหรือไม่มี `Member` ก็ได้ `checkCustomerStatus()` บอกว่าผูกสมาชิกแล้วหรือยัง
3. **Member** เก็บชื่อ เบอร์ แต้ม และประวัติแต้ม `earnPoints()` เพิ่มแต้ม `redeemPoints()` หักแต้ม ส่วน `setRule()` เปลี่ยนกฎกลางของร้าน
4. **Table** เก็บรหัสโต๊ะและ QR ใน Terminal การสแกนเป็นการจำลอง: `scanTableQRCode()` บันทึกว่าสแกนแล้ว และ `identifyTableNumber()` คืนรหัสโต๊ะ

### อาหารและคู่มือ

5. **Menu** เก็บชื่อ ราคา หมวด สถานี สถานะขาย ตัวเลือก และสูตรหลายเวอร์ชัน `openSale()` เปิดขายได้เมื่อมีสูตรสมบูรณ์
6. **Recipe** เก็บเวอร์ชันและ List สองชุด เช่น `ingredients.get(0)` เป็นปลา และ `quantities.get(0)` เป็น 0.15 กก. ต่อจาน สูตรที่สมบูรณ์แล้วต้องสร้างเวอร์ชันใหม่ก่อนแก้
7. **SOP** คือคู่มือของเมนูหนึ่งรายการ เก็บขั้นตอนหลายข้อและรวมเวลามาตรฐานด้วย `getTotalMinutes()`
8. **SOPStep** คือขั้นตอนหนึ่งข้อ มีลำดับ คำอธิบาย และจำนวนนาทีมาตรฐาน

### ออเดอร์และการเงิน

9. **Order** คือออเดอร์ทั้งใบ อ้างถึงโต๊ะ ลูกค้า และรายการอาหารหลาย `OrderItem` เมธอด `confirm()` ตรวจสต็อกก่อนยืนยัน
10. **OrderItem** คืออาหารหนึ่งบรรทัด เช่น กะเพราปลา 2 จาน เก็บราคา สูตร ตัวเลือก และสถานะของตัวเอง จึงปรุงหรือยกเลิกแยกจากอาหารบรรทัดอื่นได้
11. **Payment** คือการชำระหนึ่งใบ `pay()` เตรียมยอดเงิน/ส่วนลด ส่วน `confirm()` จึงหักแต้ม เพิ่มแต้ม และปิดออเดอร์จริง
12. **PointTransaction** คือประวัติแต้มหนึ่งครั้ง บอกว่าเพิ่มหรือแลกกี่แต้ม และยอดหลังรายการเท่าไร

### คลังวัตถุดิบ

13. **Ingredient** เก็บยอดคงเหลือและขั้นต่ำ `deduct()` หักยอด `restore()` คืนยอด `receive()` รับเข้า ทุกการเปลี่ยนยอดจะเพิ่มประวัติ
14. **StockMovement** คือประวัติสต็อกหนึ่งครั้ง บอกชนิด จำนวนที่เปลี่ยน ยอดคงเหลือ เหตุผล และผู้ทำ
15. **Supplier** คือผู้จำหน่าย เก็บวัตถุดิบที่ส่งได้ `supplies()` ใช้ตรวจชนิดก่อนสั่งซื้อ
16. **PurchaseOrder** คือใบสั่งซื้อวัตถุดิบ ใช้ List สามชุดเก็บวัตถุดิบ จำนวนสั่ง และจำนวนรับจริงตามตำแหน่งเดียวกัน `receive()` เพิ่มสต็อกเมื่อข้อมูลครบและถูกต้อง

`enum` เช่น `Role` และ `OrderStatus` อยู่ภายในไฟล์ของคลาสนั้น จึงยังมีไฟล์ model **16 ไฟล์**

## 5. ตามรอยหนึ่งออเดอร์แบบทีละขั้น

### ขั้นที่ 1: สแกนโต๊ะและเปิดตะกร้า (UC01)

`Main.uc01()` ให้เลือกโต๊ะ เรียก `table.scanTableQRCode()` แล้วสร้าง `Customer` ถ้ากรอกเบอร์สมาชิกและค้นพบ จะผูก `Member` กับ `Customer` จากนั้นสร้าง `Order` ในสถานะ `CART` หรือ “ตะกร้า”

```java
Customer customer = new Customer(newId("CUS"));
customer.linkMember(member); // ทำเฉพาะเมื่อค้นสมาชิกพบ
Order order = new Order(newOrderId(), table, customer);
```

### ขั้นที่ 2: เพิ่มอาหาร

`order.addItem(menu, quantity, spice, note)` สร้าง `OrderItem` หนึ่งบรรทัด `OrderItem` คัดลอกราคา สูตร และปริมาณวัตถุดิบ ณ ตอนนั้น หากเมนูเปลี่ยนราคาในวันหลัง บิลเก่าไม่เปลี่ยน ตัวเลือก เช่น เพิ่มไข่ดาว จะเพิ่มทั้งราคาและวัตถุดิบที่ต้องใช้

### ขั้นที่ 3: ยืนยันและตัดสต็อก

`order.confirm()` รวมวัตถุดิบที่ต้องใช้จากทุกรายการ ตรวจว่าทุกชนิดพอ **ก่อน** ตัดจริง หากชนิดใดไม่พอ จะไม่ตัดชนิดอื่นไปครึ่งทาง หลังตรวจผ่านจึงเรียก `ingredient.deduct(...)` และเปลี่ยนสถานะออเดอร์เป็น “ยืนยันแล้ว”

สูตรคิดวัตถุดิบคือ `ปริมาณต่อจาน × จำนวนจาน` เช่น ปลา 0.15 กก. ต่อจาน × 2 จาน = 0.30 กก.

### ขั้นที่ 4: ครัวปรุงและเสิร์ฟ (UC03)

พนักงานเลือกสถานีครัว `Main.uc03()` หารายการที่อยู่ในคิว แล้วเรียก `item.startCooking(cook, sop.getTotalMinutes())` เพื่อจดเวลาเริ่ม เมื่อเสร็จเรียก `item.markReady()` เพื่อจดเวลาจบ จากนั้น `item.serve(cashier)` เปลี่ยนสถานะเป็นเสิร์ฟแล้ว `order.refreshStatus()` สรุปสถานะทั้งใบจากรายการที่ยังไม่ถูกยกเลิก

หากอาหารเริ่มปรุงแล้ว ลูกค้าจะยกเลิกตรง ๆ ไม่ได้ ต้องส่ง `requestChange()` ให้ผู้จัดการพิจารณาใน UC08 ก่อน

### ขั้นที่ 5: ชำระเงิน (UC04)

`Payment` จ่ายได้เมื่ออาหารที่ยังไม่ยกเลิกเสิร์ฟครบ `pay()` คำนวณยอด แต่ยังไม่เปลี่ยนแต้มจริง `confirm()` ทำการหักแต้มที่แลก เพิ่มแต้มจากยอดสุทธิ จดเวลา และให้ `Order` เปลี่ยนเป็น “ชำระแล้ว” การเรียก `confirm()` ซ้ำถูกปฏิเสธ

```text
ยอดอาหาร 233 บาท
ใช้แต้ม 10 แต้ม × 1 บาท = ส่วนลด 10 บาท
ยอดสุทธิ 223 บาท
จ่ายเงินสด 250 บาท → เงินทอน 27 บาท
แต้มใหม่ที่ได้รับ = 223 ÷ 50 ปัดเศษลง = 4 แต้ม
```

ถ้าสมาชิกเดิมมี 46 แต้ม หลังใช้ 10 และได้เพิ่ม 4 จะเหลือ 40 แต้ม ตัวเลขนี้เป็นตัวอย่างเมื่อกฎแต้มยังเป็นค่าเริ่มต้น

### ขั้นที่ 6: รายงาน (UC06)

`Main.printSales()` วนอ่านออเดอร์ที่เกิดขึ้นจริง ตรวจวันที่ของ `Payment` และรวมยอดสุทธิ แยกเงินสด/QR นับจำนวนจานของแต่ละเมนู แล้วเรียงอันดับด้วยลูปพื้นฐาน ข้อมูลรายงานจึงขึ้นกับรายการที่ผู้ใช้ทำระหว่างเปิดโปรแกรม

## 6. หน้าที่ของเมนูทั้ง 8 งาน

| เมนู | เมธอดใน Main | ลำดับที่ควรเล่า |
|---|---|---|
| 1 สั่งอาหาร | `uc01()` | สแกนโต๊ะ → ผูกสมาชิก → เพิ่ม/แก้ตะกร้า → ยืนยัน → ติดตาม/ขอแก้ |
| 2 คู่มือ SOP | `uc02()` | สร้างคู่มือและขั้นตอน → เผยแพร่ → ปิด/เปิดใช้ |
| 3 ครัว | `uc03()` | เลือกสถานี → ดูรายการ → เริ่มปรุง → ทำเสร็จ → เสิร์ฟ |
| 4 ชำระเงิน | `uc04()` | เลือกออเดอร์ที่เสิร์ฟครบ → ใช้แต้ม → จ่าย → ยืนยัน → ใบเสร็จ |
| 5 สต็อก | `uc05()` | ดูยอดต่ำ → ออก PO → รับของจริง → ปรับยอด/ดูประวัติ |
| 6 รายงาน | `uc06()` | เลือกวัน → รวมบิลจริง → แยกช่องทาง → จัดอันดับเมนู |
| 7 เมนู/สูตร | `uc07()` | สร้างเมนู → สร้างสูตร → ทำสูตรสมบูรณ์ → เปิดขาย/เพิ่มตัวเลือก |
| 8 สมาชิก | `uc08()` | สมัคร/ค้นหา → ดูแต้ม → แก้ข้อมูล/กฎ → ผู้จัดการพิจารณาคำขอ |

## 7. ตัวอย่าง P4 ที่ลองรันได้

ข้อมูลตัวอย่าง P4 ใน `createSampleData()` มีเมนูผัดกะเพราปลา ราคา 69 บาท ตัวเลือกเพิ่มไข่ดาว 15 บาท และยำหมูยอ/แหนม 65 บาท หากสั่งกะเพราปลา 2 จานพร้อมไข่ดาวทั้ง 2 จาน และยำ 1 จาน จะได้:

```text
กะเพราปลา 2 × (69 + 15) = 168 บาท
ยำหมูยอ/แหนม 1 × 65 = 65 บาท
รวม 233 บาท
ปลาเริ่ม 5.3 กก. ใช้ 0.3 กก. เหลือ 5.0 กก.
ไข่เริ่ม 3 ฟอง ใช้ 2 ฟอง เหลือ 1 ฟอง
```

## 8. คำถามที่มักถูกถามตอนนำเสนอ

**ทำไมมี Constructor แล้วยังมีเมธอดอ่านข้อมูล?** Constructor ตั้งค่าเริ่มตอน `new` แต่ `Main` ต้องอ่านชื่อ ราคา สถานะ และยอดไปแสดง จึงต้องมีเมธอดอ่านข้อมูลเมื่อ field เป็น `private`

**ทำไมยังมีเมธอดเปลี่ยนข้อมูล?** ข้อมูลบางอย่างเปลี่ยนหลังสร้าง object เช่น ชื่อ/เบอร์สมาชิกและหมายเหตุอาหาร จึงใช้ `rename()`, `changePhone()` หรือ `changeNote()` ส่วนข้อมูลที่มีกฎหลายขั้น เช่น สต็อกหรือการชำระ ใช้ `deduct()` และ `confirm()`

**ทำไม OrderItem เก็บราคาและสูตรซ้ำจาก Menu?** เพื่อรักษาข้อมูลตอนสั่ง เมนูหรือสูตรที่แก้ภายหลังไม่ควรเปลี่ยนยอดและวัตถุดิบในบิลเก่า

**ทำไมต้องตรวจสต็อกให้ครบก่อนตัด?** ถ้าปลาพอแต่ไข่ไม่พอ ออเดอร์ต้องไม่สำเร็จ และยอดปลาไม่ควรถูกตัดไปก่อน

**ทำไมใช้ List หลายชุด?** เพื่ออธิบายด้วยตำแหน่งที่มองเห็นได้ง่าย เช่น `ingredients.get(0)` คือปลา และ `quantities.get(0)` คือปริมาณปลา เมธอด `addItem()` เพิ่มทั้งคู่พร้อมกัน จึงต้องดูแลให้ List ทุกชุดมีลำดับตรงกัน

**`enum` ต่างจาก String อย่างไร?** `enum` จำกัดค่าให้เลือกเฉพาะที่กำหนด เช่น `OrderStatus` ป้องกันสะกดสถานะผิด ส่วน `statusText()` แปลงเป็นภาษาไทยเพื่อแสดงหน้าจอ

**has-a ต่างจาก Composition อย่างไร?** has-a หมายถึง object หนึ่งมีความสัมพันธ์กับอีก object เช่น `Order` อ้างถึง `Table` แต่การลบ `Order` ไม่ได้ลบโต๊ะ ส่วน Composition คือ has-a แบบเป็นเจ้าของส่วนย่อย เมื่อทำลายตัวหลักจะทำลายส่วนย่อยตาม ในโค้ดมี 5 คู่: `Order`–`OrderItem`, `Menu`–`Recipe`, `SOP`–`SOPStep`, `Ingredient`–`StockMovement`, `Member`–`PointTransaction` เมธอด `destroy()` เป็นเมธอดที่เราเขียนเอง ไม่ใช่คำสั่งลบหน่วยความจำของ Java

| เจ้าของ (Composition) | ส่วนย่อย | หลักฐานในโค้ด |
|---|---|---|
| `Order` | `OrderItem` | `Order.destroy()` เรียก `destroy()` ของรายการอาหาร |
| `Menu` | `Recipe` | `Menu.destroy()` ทำลายสูตรทุกเวอร์ชัน |
| `SOP` | `SOPStep` | `SOP.destroy()` ทำลายขั้นตอนทุกข้อ |
| `Ingredient` | `StockMovement` | `Ingredient.destroy()` ทำลายประวัติของวัตถุดิบนั้น |
| `Member` | `PointTransaction` | `Member.destroy()` ทำลายประวัติแต้มของสมาชิกนั้น |

ตัวอย่าง **has-a แบบ Association** คือ `Customer` อ้างถึง `Member`, `Order` อ้างถึง `Table`, `PurchaseOrder` อ้างถึง `Supplier` และ `Recipe` อ้างถึง `Ingredient` การทำลาย object ฝั่งแรกไม่ทำลายอีกฝั่ง คอมเมนต์ใกล้ field ในแต่ละคลาสระบุความสัมพันธ์เหล่านี้ไว้แล้ว

**โค้ดตรง P7 ทุกตัวอักษรไหม?** ชื่อ operation หลักทั้ง 73 รายการอยู่ในโค้ด แต่จำนวน field/method ยังมากกว่า P7; field ที่ P7 เขียนเป็น `Map` ถูกเปลี่ยนเป็น `List` ตามฉบับเรียนรู้ และมีข้อมูลเสริมเพื่อให้ทั้ง 8 งานทำงานได้จริง ดู `P9/P7-STRICT-AUDIT.md`

**ข้อมูลถูกเก็บถาวรไหม?** ยังไม่ถาวร ข้อมูลอยู่ในหน่วยความจำ ปิดโปรแกรมแล้วกลับไปใช้ข้อมูลตัวอย่างชุดเดิมเมื่อเปิดใหม่

## 9. ลำดับอ่านโค้ดและฝึกพูด

1. เปิด `src/Main.java` อ่าน `main()` และ `createSampleData()` เพื่อเห็นจุดเริ่มกับ object ตัวอย่าง
2. อ่าน `Table`, `Customer`, `Employee` เพื่อเข้าใจ Constructor, field และเมธอดอ่านข้อมูล
3. อ่าน `Menu`, `Recipe`, `Ingredient` เพื่อดูความสัมพันธ์ระหว่างเมนู สูตร และคลัง
4. อ่าน `Order.addItem()`, `Order.confirm()` และ `OrderItem` เพื่อเห็นการสั่งอาหารจริง
5. อ่าน `Payment.pay()`, `Payment.confirm()` และ `Member` เพื่ออธิบายเงินกับแต้ม
6. กลับไปอ่าน `uc01()` ถึง `uc08()` ทีละเมนูตามที่จะสาธิต

ประโยคสรุปสำหรับนำเสนอ: “Main รับคำตอบและเรียกงาน ส่วน model แต่ละ object เก็บข้อมูลและตรวจเงื่อนไขของตัวเอง เมื่อยืนยันออเดอร์ Order ตรวจสต็อกทุกชนิดก่อนตัด เมื่อชำระ Payment จึงเปลี่ยนแต้มและปิดออเดอร์ ข้อมูลชุดเดียวกันถูกใช้ต่อในครัว สต็อก และรายงาน”
